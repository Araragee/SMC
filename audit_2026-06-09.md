# SMC System Audit — 2026-06-09

Scope: backend (FastAPI), frontend (Vue 3 + Pinia), session lifecycle, auth, shop, messaging, notifications. Findings ranked by impact. Each item is intentionally specific (file:line where possible) so it can be picked up directly.

---

## 1. Foolproofing the user — what's missing

### 1.1 Session lifecycle gaps (highest impact)

**(a) Student cannot cancel their own confirmed session.** `routers/sessions.py` has approve/reject/counter/complete, but no `cancel` for student or teacher. The only escape hatches are admin bulk-cancel and admin edit. A student who books a session and then gets sick has nowhere to go in the UI — they must DM admin. Add `POST /sessions/{id}/cancel` accepting student or teacher, with a guard like "must be ≥X hours before start_time" and an admin override.

**(b) Teacher cannot upload proof from the UI.** `POST /session-proofs/` accepts both roles (`routers/sessions.py:1339`), but I find no frontend caller for it (`grep session-proofs` only returns it in unrelated stores). The teacher proof column in `SessionDetailModal` always shows "Pending" with a nudge button — there's no upload affordance. Fix: add an "Upload my proof" button visible to the participant who hasn't uploaded yet, on any of `scheduled / overdue / overdue_rejected / pending_verification`.

**(c) `request-approval` endpoint hard-requires student proof only.** `routers/sessions.py:992` checks `uploader_role == 'student'`, so a teacher-only proof can never advance an overdue session. Either accept either role's proof or make the rule explicit in the UI ("Student proof required to submit"). Right now the user gets a generic 400.

**(d) Stale `pending_admin`.** A session sitting in `pending_admin` has no SLA reminder. `session_checker_task` only nags `pending_verification` and `overdue_rejected`. Add the same stale-cutoff treatment for `pending_admin` (and `pending_teacher` / `pending_student` for completeness) so proposals don't rot.

**(e) `nudge_session` has no authorization gate.** Anyone with a valid token can nudge any session by ID (`routers/sessions.py:1023`). Rate-limited per IP+session, yes, but a malicious student could enumerate IDs and spam every teacher in the school. Add: caller must be a participant or admin.

**(f) `notes` field has no length limit.** `SessionPropose`, `SessionEdit`, `SessionApproval`, `SessionCounter` all accept unbounded strings. Same for `proof_justification`, `rejection_reason`, `Homework.description`, `Order.notes`, `Payment.notes`. SQLite swallows it; PostgreSQL won't care either, but the UI will explode rendering 200KB strings. Add `max_length` to every Pydantic string field, e.g. `Field(max_length=500)`.

**(g) Counter-proposal loop has no cap.** Teacher and student can volley `pending_teacher ↔ pending_student` forever, each bump invalidating the other's locks. Add a `counter_count` column (or check history) and force admin involvement after, say, 3 round-trips.

**(h) Proof upload accepts ≤10 MB images but no normalization.** A user uploading a phone photo at 12MP gets a 9MB file persisted as-is — the lightbox in `SessionDetailModal` will choke on slower devices. Either downscale on the server (Pillow) or set max edge to 2000px.

### 1.2 Auth & account safety

**(i) Default admin password is settable via `.env` but there's no first-login forced rotation.** `_seed_defaults()` (`main.py:42-58`) just creates the admin with whatever `DEFAULT_ADMIN_PASSWORD` is set to. Add a `must_change_password` flag on the User model and gate the dashboard behind a password-change flow when true.

**(j) No email-verification gate.** `email_verified` exists on `User` (`models.py:81`) and there's a `send_verification` endpoint, but no router enforces it for sensitive actions (payments, profile edits). Either drop the field or wire it to `require_verified_email` for actions that need it.

**(k) No "forgot password" UI.** `/auth/forgot-password` and `/auth/reset-password` exist server-side, but `grep forgot` in `frontend/src` returns zero matches. Add a link on the Login page and the matching `/forgot-password` and `/reset-password?token=...` routes.

**(l) `get_current_user` does not check that the JWT's `exp` matches the user's `is_active` snapshot.** A user deactivated by admin keeps working until their 15-minute access token expires. Either keep ACCESS_TOKEN_EXPIRE_MINUTES short (it's already 15) and accept it, or check `iat`/`token_jti` on each request. The current 15-minute window is probably fine — call this out so it's a deliberate choice, not a hidden bug.

**(m) Refresh token in `localStorage`.** `auth.ts:107` writes the refresh token to localStorage. Any XSS = full account compromise. Move refresh token to an HttpOnly cookie; keep the short-lived access token in memory.

### 1.3 Foolproofing forms and inputs

**(n) `ProposeSessionModal` has no past-date guard.** Backend will happily accept a `start_time` in the past from a student propose call. Block it client-side AND server-side: reject if `start_time < now - 5min` on `propose/*` endpoints.

**(o) Session duration validation is missing.** `end_time` only defaults to start+1h if omitted; if both are sent and end ≤ start, only `create_recurring_sessions` checks it. The single-session propose/edit endpoints will accept a 0-minute or negative-duration session. Add `_validate_duration(start, end, min_minutes=15, max_minutes=240)` and call it everywhere.

**(p) Scheduling outside working hours / weekends has no rule.** A student can propose a 3am Sunday lesson. Add a configurable working-hours window in settings.

**(q) Confirmation dialogs missing on destructive actions.**
- `delete_user` (`users.py:195`): no "type the user's name to confirm" pattern.
- `delete_payment` (`payments.py:189`): destructive and there's a router-level activity log, but no UI confirm beyond the basic dialog.
- Bulk cancel: confirms count, but does not warn "X of these are already completed and will be reverted (sessions_left will be refunded)".

**(r) `SessionDetailModal` shows nudge button even when no participants exist on a session that's already in `pending_verification`.** Worth disabling the button entirely when no upload is outstanding.

### 1.4 Data-integrity foolproofing

**(s) `delete_session` for a `completed` session refunds sessions_left without checking it's the most-recent enrollment.** If the student moved teachers since, the refund goes to the wrong enrollment counter (`sessions.py:564-574`). Match the enrollment by `created_at`-most-recent or refuse to delete completed sessions older than X days.

**(t) `recalculate_student_sessions` is admin-only, but there's no scheduled audit.** Drift between `users.sessions_left` and `Σ(enrollments.purchased - used)` is silent until someone clicks the button. Run the recalculation nightly in `session_checker_task` and log + notify admin if any user's drift > 0.

**(u) Enrollment delete subtracts only `remaining` from `sessions_left` but not `sessions_used`.** If a student already consumed 3 of 10 sessions in an enrollment that's then deleted, those 3 completed sessions still point at a missing enrollment. Either refuse to delete enrollments that have `sessions_used > 0` or soft-delete with `is_active`.

**(v) Recurring session creation isn't atomic.** `create_recurring_sessions` (`sessions.py:351`) does `db.add` + `db.flush` per occurrence inside a single transaction, but if `_check_overlap` raises on occurrence #7, sessions 1–6 are rolled back. That's fine — but the user gets a confusing "scheduling conflict at session 7" with zero context. Either pre-check all 12 dates up front, or return `created_ids` so the admin sees which dates failed.

## 2. UI/UX gaps that hurt without sacrificing the design

### 2.1 Calendar (`BaseCalendar.vue`)

- **Week-only view.** Users can't see "this month at a glance" — admin Schedule has 200+ sessions and no month grid. Add a view toggle: Week / Month / Day.
- **Sessions overflow.** A day with 8 sessions just stacks them; the day cell grows the row. Add `+N more` overflow with a popover.
- **No drag-and-drop reschedule for admin.** Native HTML5 DnD or vue-draggable on admin Schedule would massively cut the friction of "move that lesson 30 min later."
- **No keyboard navigation.** Arrow keys to move week, Enter to open day. Calendars without this fail accessibility checks.
- **Legend is hidden inside the calendar card.** Move it to a `?` popover or collapse it on mobile — it's noisy on a 7-day strip.

### 2.2 Session detail modal

- **No "view history" for a session.** Negotiated sessions have a hidden trail. Surface the activity log entries filtered to `target_type=session, target_id=N` inside an expand panel.
- **No "copy session link" / deep-link to the modal.** Admins can paste `?session_id=N` to jump in, but there's no button to copy that URL.
- **No keyboard shortcut to approve/reject** the highlighted session. Add `A` / `R` / `C` (counter) when modal is open.
- **The `canForceComplete` countdown isn't shown.** "Force Complete (available in 24h)" — but no live timer. Show "available in 4h 12m".
- **Lightbox doesn't support arrow-key navigation** between proofs.

### 2.3 Notifications

- **Notification list lacks filtering.** A heavy user gets dozens per day; there's no filter by type or "show only unread", no bulk-mark-as-read.
- **No notification preferences.** All-or-nothing. Add per-channel toggles (24h reminder, 12h reminder, nudge received, proof rejected, etc.) so power users can mute noise.
- **No in-app badge on the nav.** Mobile dock and floating navbar don't expose the unread count. Currently you have to open the panel to see it.
- **Notifications never auto-expire.** Table will grow forever. Add a 90-day retention purge in `session_checker_task`.

### 2.4 Messaging

- **No typing indicators / read receipts in WebSocket schema.** Worth adding — the infra is already there.
- **No file/image attachments.** The session_thread is the natural place to attach a quick "here's the chord chart" — currently text only.
- **No search across conversations.**

### 2.5 Shop & orders

- **No partial fulfillment.** An order is fulfilled or not — but if 3/4 items are in stock, admin has to manually note it.
- **No order-history filter / search** in `views/teacher/Shop.vue` (which is a 7-line stub! — see issue 4.b below).
- **No cart persistence across reloads** — check `stores/shop.ts` for that.
- **Shop low-stock notifications fire on every approval** when stock < 5. Add a "we already notified you about this in the last 24h" cooldown so admin doesn't get the same alert 4 times in a day.

### 2.6 Mobile

- `views/teacher/Shop.vue` is 7 lines — a placeholder. Either implement it or hide the dock entry for teachers.
- `BaseCalendar.vue` has `min-w-[700px]` and horizontal scroll on small screens — works, but the bottom nav `MobileDock` can overlap the legend. Add safe bottom padding (`pb-28` is on some views, not all).
- Long names truncate ungracefully — no tooltip on hover for full name.

### 2.7 Accessibility

- Material Symbols icons are decorative but missing `aria-hidden`. They're announced by screen readers as "calendar_month icon".
- Color is the only differentiator on status badges — users with color blindness can't tell `pending_teacher` (amber) from `pending_student` (orange). The label text helps; the calendar pills don't always include it on narrow widths.
- No focus-visible styles on custom buttons (`focus:ring` is inconsistent across `BaseButton`, action buttons in `SessionDetailModal`, etc.).
- No `prefers-reduced-motion` respect on the modal transitions.

## 3. System stability & integrity

### 3.1 Concurrency

- Optimistic locking with `version` is great — but `nudge` and notification-only updates (24h/12h reminders) intentionally skip bumping it, which is correct. Document this in `_check_version`'s docstring.
- `complete_session_as_admin` and `record_past_session` both atomically decrement `sessions_left` ✓ but use Enrollment ORM update (`enrollment.sessions_used += 1`). That's a read-modify-write race. Convert to `text("UPDATE enrollments SET sessions_used = sessions_used + 1 WHERE id = :eid")`.
- The 1-min `session_checker_task` runs queries even when there are no sessions of interest. The `has_scheduled` short-circuit only covers the scheduled-reminder block — the stale-reminder query still runs every minute. Negligible at small scale, worth re-checking at 10k users.

### 3.2 Background task resilience

- `session_checker_task` swallows exceptions per loop iteration with `db.rollback()` — good. But if the loop crashes between `try` and `finally`, the asyncio task dies silently and reminders stop forever. Wrap the outer `while True` in another guard and `logger.critical(...)` + restart on outer failure.
- Token purge runs once per 24h on the background task — fine; but if the server restarts every 6h (rolling deploys), purge effectively never runs. Move to a separate cron/scheduled job, or trigger on startup too (already does, via `_purge_stale_tokens` in `main.py:67` ✓).

### 3.3 Database

- **No Alembic migration referenced for several new columns** I can see in the model (`is_force_completed`, `version`, `stale_reminded_at`, lockout fields). `models.py` has comments saying "MIGRATION NOTE: run alembic revision". Generate and commit those — adopting from a fresh DB will explode otherwise.
- **`Conversation.type` is a freeform string** — should be a CHECK constraint or an Enum.
- **No index on `Session.end_time`** but the `overdue` check filters by it every minute. Add `Index("ix_sessions_status_end_time", "status", "end_time")`.
- **No index on `Notification.created_at`** — when you build the 90-day purge, this matters.
- **`User.username` and `User.email` are both nullable + unique** (`models.py:55, 62`). Multiple NULL values are allowed in SQLite + Postgres for nullable uniques, which is OK, but the seed/default-admin code at `main.py:60-62` shows we already had to repair this. Make them NOT NULL with a NUL placeholder if you can.

### 3.4 Security hardening

- **CORS is dev-only** (`config.py:50`) — fine, but make sure `ALLOWED_ORIGINS` is overridden in prod via env, not hardcoded.
- **`/uploads` is publicly served** with no auth (`main.py:114`). A user with a leaked proof URL can view any other student's proof. Either generate signed URLs or require a session cookie on `/uploads/proofs/*`.
- **CSP / security headers** — no middleware sets `Content-Security-Policy`, `X-Content-Type-Options`, `Referrer-Policy`, `Strict-Transport-Security`. Add a `SecurityHeadersMiddleware`.
- **Rate limits** are per-endpoint and per-IP — behind a proxy, every user looks like the same IP. Make sure the deployment sets `X-Forwarded-For` and slowapi reads it.
- **`debug_users` endpoint** (`users.py:29`) checks `settings.DEBUG` but is only excluded from the OpenAPI schema, not the routing — a curl request still hits it (and then 404s). Skip the route registration entirely when `not DEBUG`.

### 3.5 Test coverage

- Only `test_main.py` exists in the backend. The whole session state machine deserves unit tests: every transition, every illegal transition, version conflict, overlap conflict, force-complete window, etc. Same for the 2FA flow.
- No frontend tests at all. Vitest + a single happy-path test per role would prevent regressions.

## 4. Implementation suggestions (ordered by ROI)

I'd tackle these in this order:

a. **Add the missing student/teacher cancel + teacher proof upload UI** (closes the biggest "I'm stuck" UX hole; ~½ day backend + 1 day frontend).
b. **Implement teacher Shop view** (currently a 7-line stub — it's broken-looking).
c. **Forgot-password UI** + `/forgot-password` + `/reset-password` routes (server is already there).
d. **Add `cancel` reasons everywhere** + Pydantic `max_length` on every string field (small change, big robustness).
e. **Working-hours / past-date / duration validators on propose endpoints.**
f. **Signed URLs (or auth-checked redirect) for `/uploads/proofs/*`** (privacy gap).
g. **Auth: move refresh token to HttpOnly cookie**, force-change-password on default admin first login.
h. **Month view + drag-reschedule on admin calendar.**
i. **Notification preferences + auto-purge + unread badge in navbar.**
j. **Audit log "history" tab inside `SessionDetailModal`.**
k. **Nightly `sessions_left` recalculation + drift alert.**
l. **Backend + frontend tests around the session state machine** (high-leverage safety net before shipping more features).
m. **Accessibility pass** (aria-hidden on icons, focus rings, reduced-motion).

## 5. Notable things already done right

So the report isn't only negative:

- Optimistic locking on Sessions with `version` is properly threaded through every transition.
- Atomic SQL `UPDATE ... WHERE sessions_left > 0` for the race condition is exactly right.
- TOTP secret Fernet-encrypted at rest with transparent legacy migration — clean.
- Account lockout after 5 failed logins (`users.py:26-27, 65-79`).
- Refresh-token rotation with reuse detection that revokes the whole chain (`auth.py:117-119`).
- Magic-byte validation on uploads (`utils/uploads.py`) — most schools never do this.
- Stale-state reminder cooldowns (`stale_reminded_at`) so users aren't spammed.
- Activity log with actor snapshot — survives user deletion.

Solid foundation. The list above is mostly polish, foolproofing, and tightening — not architectural rewrites.
